# voltage_display_ip

Target integration baseline: GitHub repository
`jbt9412-wq/007_Basys3_SoC_Redundant_UART_Link`, `main` commit
`b3cc5ea2988418f53e49c3084a9b116745bb17ba`.

## Interface

| Port | Direction | Width | Meaning |
|---|---:|---:|---|
| `clk` | input | 1 | 100 MHz clock |
| `reset_p` | input | 1 | active-high asynchronous reset |
| `current_adc` | input | 12 | latest ADC code held by Sensor Guard |
| `display_valid` | input | 1 | level-valid indication held by Sensor Guard |
| `an` | output | 4 | active-low Basys3 digit anodes |
| `seg` | output | 7 | active-low `{g,f,e,d,c,b,a}` segments |
| `dp` | output | 1 | active-low decimal point |

There is no AXI interface, memory map, base address, register map, interrupt,
LED output or XADC logic.

## Display behavior

For a valid input:

```text
millivolt = (current_adc * 3300 + 2047) / 4095
display   = digit3.digit2digit1digit0
range     = 0.000 to 3.300
```

The constant divide by 4095 is implemented with an exact shift/add correction
identity, and BCD conversion uses combinational Double-Dabble; no variable
divider is present. The result is saturated at 3300 mV. For an invalid input all four digits show
`----` and the decimal point is off.

`an[3]` is the leftmost digit and `an[0]` the rightmost. The scan order is
`an=1110, 1101, 1011, 0111`. The default `SCAN_TICK_CYCLES=100000` gives 1 ms
per digit and a 250 Hz four-digit refresh rate at 100 MHz.

At the digit3-to-digit0 frame boundary, `current_adc` and `display_valid` are
captured together. The captured pair remains unchanged for the next complete
frame. Input or validity changes therefore cannot mix digits in one frame and
are applied within one four-digit frame.

During `reset_p=1`, `an=1111`, `seg=1111111`, and `dp=1`.

## Integration rule

Do not connect two sources to the same FND ports. The integration owner must
leave `redundant_link_core.led[15:0]` connected, disconnect the Core's
`seg/dp/an`, and connect this IP's `seg/dp/an` to the existing external
`seg_0/dp_0/an_0` ports. This package does not modify `status_display.v`, the
Core, Block Design, XDC, bitstream, XSA or Vitis sources, and contains no pin
XDC.

## Verification and packaging

In Vivado 2024.2:

```bash
mkdir -p reports
vivado -mode batch \
  -source scripts/package_voltage_display_ip.tcl \
  -log reports/package_voltage_display_ip.log \
  -journal reports/package_voltage_display_ip.jou
```

The script runs the Verilog-2005 self-checking testbench, writes a VCD, performs
out-of-context synthesis for `xc7a35tcpg236-1` with a 10 ns clock, writes
utilization/timing/methodology/DRC reports, and packages
`user.org:user:voltage_display_ip:1.0`.

The testbench exhaustively compares both ADC-to-millivolt conversion and all
four BCD digits for all 4096 ADC input codes. It also checks reset, invalid
display, all decimal segment fonts, scan order, one-active-anode behavior,
decimal-point position, frame-consistent ADC changes and invalid/valid
transitions.

The successful testbench terminal line is:

```text
VOLTAGE_DISPLAY_IP TEST PASS
```

Do not claim validation success unless:

- `reports/simulation_xsim.log` contains that exact PASS line and no test
  `ERROR:` or `TEST FAIL` line;
- `reports/timing_metrics_ooc.txt` shows `WNS >= 0`, `TNS = 0.000 ns`,
  `WHS >= 0` and `THS = 0.000 ns`;
- `reports/validation_summary.txt` shows zero errors and zero critical
  warnings;
- `packaged_ip/voltage_display_ip_1.0/component.xml` was regenerated by the
  same run and IP integrity passed.

The same run also creates:

```text
reports/voltage_display_ip.vcd
reports/utilization_ooc.rpt
reports/timing_summary_ooc.rpt
reports/timing_metrics_ooc.txt
reports/methodology_ooc.rpt

```

The included `reports/simulation_xsim.log` and
`reports/voltage_display_ip.vcd` were generated by the final Vivado 2024.2

timing, IP-integrity and packaging transcript. See `VERIFICATION_STATUS.md`
